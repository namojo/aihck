# 하네스 설계 — 왜 이 구조인가

## 1. 하네스란

모델은 바뀌어도 그대로 남는 것, 즉 모델을 둘러싼 도구·스키마·검증·루프가 하네스다. 비유하면 모델은 운전자, 하네스는 차선·계기판·안전벨트다. 운전자가 아무리 좋아도 계기판 없이는 과속을 모른다. 이 프로젝트의 하네스는 네 가지로 이루어진다.

| 구성 | 역할 | 어디 |
| --- | --- | --- |
| 결정적 뼈대 | 파싱, 규칙 엔진, 배점표 탐지, 산출물 생성. 같은 입력이면 같은 출력 | `parse.py`, `risk.py`(규칙 부분), `toc.py`(탐지 부분), `export.py` |
| 스키마 계약 | LLM이 돌려줄 수 있는 모양을 pydantic으로 고정. 틀리면 재시도, 두 번 틀리면 실패로 기록 | `schemas.py`, `llm.py` |
| 검증 장치 | 인용문이 원문에 실제로 있는지, 배점 합이 맞는지, 근거 문단 id가 존재하는지 코드로 확인 | `extract._quote_found`, `toc flags`, `coverage valid ids` |
| 측정 루프 | 골든셋 대비 재현율·정밀도를 기록하고 담당 에이전트에게 개선 한 가지를 넘김 | `eval/`, `eval-judge` 에이전트 |

## 2. LLM을 쓰는 곳과 안 쓰는 곳

| 단계 | LLM | 이유 |
| --- | --- | --- |
| parse | 안 씀 | 틀리면 뒤 단계가 다 틀린다. 결정적이어야 디버깅이 된다 |
| extract | 씀 | 표 밖 문장에서 요구사항을 알아보는 일은 규칙으로 못 한다 |
| toc 탐지 | 안 씀 | 배점표는 "배점" 열과 숫자 합으로 찾을 수 있다 |
| toc 연결 | 씀 | 요구사항과 배점 항목의 의미 연결은 판단이다 |
| risk 탐지 | 안 씀 | 규칙은 재현 가능하고 설명 가능하다. "왜 걸렸나"를 정규식으로 보여 줄 수 있다 |
| risk 보강 | 씀 | 문맥(완화 조항, 상한)을 읽어 심각도를 조정하고 협상 문구를 쓴다 |
| coverage | 씀 | 패러프레이즈된 초안 문장이 요구사항을 덮는지는 의미 비교다 |
| export | 안 씀 | 산출물 형식은 결정적이어야 한다 |

LLM 단계마다 `mock_fn`이 있다. mock은 규칙 기반의 결정적 대체물로, 테스트와 오프라인 데모를 가능하게 한다. mock의 결과가 골든셋과 일치하도록 샘플 RFP를 설계했으므로, mock 통과는 "파이프라인 배관이 멀쩡하다"는 뜻이지 "추출 품질이 좋다"는 뜻이 아니다. 품질은 실제 모드로 측정한다.

## 3. 개발 하네스: 서브에이전트가 단계를 소유한다

`.claude/agents/`의 에이전트 7개는 각각 파이프라인 단계 하나를 소유한다. 소유한다는 것은 그 단계의 코드·프롬프트·테스트·검증 방법을 한 파일에 적어 두었다는 뜻이다. 해커톤 48시간 동안 팀원 3~4명이 각자 Claude Code 세션을 열고 "requirement-extractor로 재현율 올려줘"라고 말하면, 그 에이전트는 자기 단계의 검증 명령을 알고 있어서 바꾼 뒤 스스로 측정한다.

루프는 이렇다.

```
rfp-orchestrator 실행 → eval-judge 측정 → (떨어진 지표의 담당 에이전트) 개선 한 가지 → 재측정
```

"한 번에 하나만 바꾼다"를 eval-judge의 원칙으로 둔 이유는 간단하다. 두 가지를 바꾸면 무엇이 효과였는지 모르고, 그러면 다음에 또 두 가지를 바꾸게 된다.

## 4. 재구현 가능성

이 하네스는 Claude Code에 묶여 있지 않다. `AGENTS.md`는 도구 중립 진입점이고, `docs/SPEC.md`는 모듈별 입출력·수용 기준·테스트 명령을 적어 다른 코딩 에이전트가 처음부터 다시 만들 수 있게 했다. LLM 공급자를 바꾸려면 `llm.py`의 `LLM.parse()` 하나만 바꾸면 된다. 입력은 (system, user, pydantic 스키마), 출력은 스키마 인스턴스다.

## 5. 알고 있는 한계

- 스캔 PDF(OCR 필요)는 지원하지 않는다. `needs_ocr`로 표시만 한다.
- 선이 없는 표는 추출하지 않는다. 텍스트 전략 폴백은 본문을 가짜 표로 만들어 요구사항을 오염시켰기 때문에 껐다.
- 위험 규칙의 법령 기준값은 팀이 확인해야 한다. 규칙 파일의 `basis`에 그렇게 적어 두었다.
- 실제 모드 측정값은 이 저장소에 아직 없다. `eval/history.jsonl`에 mock 기록만 있다.
