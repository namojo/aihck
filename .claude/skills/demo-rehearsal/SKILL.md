## 점검 항목

1. `out/<demo>/checkpoints/`에 6단계가 모두 있고 `report.json`의 `summary`가 발표 슬라이드 숫자와 같다. 다르면 슬라이드를 고친다. 코드를 고치지 않는다.
2. 실제 모드로 한 번 끝까지 돌아간 기록(`out/<demo>/run.log`)이 있다. 심사장에서는 네트워크를 믿지 않는다. 체크포인트에서 `export`만 다시 돌리는 명령을 준비한다.
   ```bash
   python -m rfpharness review <pdf> --from export --out out/<demo>
   ```
3. 같은 시나리오의 녹화본(`docs/demo/demo.webm`)이 있다. 라이브가 실패하면 30초 안에 녹화본으로 전환한다.
4. 대시보드(`dashboard.html`)가 오프라인에서 열린다(외부 CDN 없음).
5. 발표 첫 장에 "데모 데이터는 가상의 기관·사업이다" 또는 "나라장터 공개 RFP(공고번호)"를 적었다.
6. 심사위원 질문 대비: "LLM이 틀리면?" → 원문 인용·페이지가 붙어 있어 사람이 10초 안에 확인한다. "기존 Copilot과 뭐가 다른가?" → 배점 기준 목차와 초안 대조는 제안 업무 전용 흐름이다.

## 출력

점검 결과를 ☑/☐ 목록으로 보여 주고, ☐가 하나라도 있으면 "데모 준비 미완료"라고 쓴다.
